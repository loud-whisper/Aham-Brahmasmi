# Security policy

Report a suspected vulnerability through this repository's **Security > Report a vulnerability** route. Private vulnerability reporting must be enabled before public release. Do not include credentials, private workspace files, personal information or sensitive reproduction data in public issues.

Include the affected version or source commit, the behavior you observed, a minimal synthetic reproduction and the expected security boundary. Redact tokens, account identifiers and local paths. A report is evidence to investigate, not permission to access another person's systems.

This preview has no guaranteed response time or security certification. Keep backups of your workspace, review permission requests and external sources, and install updates only after checking their source and scope.

If a credential may have been exposed, update its consumers and rotate or revoke it through the issuing service. Removing a file or repository does not invalidate a credential or retract outside copies.
